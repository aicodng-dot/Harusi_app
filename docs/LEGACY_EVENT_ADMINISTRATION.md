# Legacy event catalogue and metadata boundary

## IMPLEMENTED — P4-004 source and isolated tests (2026-10-22)

Legacy event catalogue and statistics now include only events with workspace_id exactly null and SQL-bounded event IDs from 1 through PHP_INT_MAX before Eloquent hydration. The admin layout uses primary filtered event queries for its selected title and active switcher; invalid/noncanonical selected IDs are ignored without rewriting the session. Direct edit/update/select/archive/cancel reread the event on the primary and return404 for workspace-owned targets before validation or navigation changes, even when the admin is a workspace owner or has the platform flag. Bound raw identities must be canonical positive PHP-range integers before casting. Update/archive/cancel repeat null ownership on a locked fresh row inside the mutation transaction. Legacy create/update ignore submitted ownership and preserve ordinary unowned controls; no global Event scope or ownership reassignment was added.

The same 98 routes remain registered. Event catalogue/create forms and ordinary unowned event edit/update/select/archive/cancel redirects retain their existing contracts. Attempts against workspace-owned event metadata use404, including malformed update input, so validation cannot expose target details. A missing or unsafe raw identity also fails before lookup. No platform/member override is introduced: customer event management must use its own explicit policies and routes in a later task.
