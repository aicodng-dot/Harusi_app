## Captured identity and one attempt

The service exposes create(array, User, selectedEventId, generateQr=true): Guest; importRow(array, policy, User, selectedEventId, generateQr): outcome/optional Guest/generated_qr; generate(Guest, User, selectedEventId, missingOnly=false): QR/generated/replaced; ensureImage(Guest, User, selectedEventId): QR. Policies are skip, reject_if_match and add_anyway. Only normalized allowlisted name, phone, pass type and allowance enter creation; Event/zero usage/active state are constructed internally. Caller ownership, manual codes, tokens, paths, counters or cached relationships supply no authority.

Canonical original/current actor, selected Event and supplied Guest identities are frozen before guard SQL. Each mutation uses exactly one default-connection transaction attempt. The current primary locked prefix is unowned selected Event -> exact active administrator -> unchanged offline Event reread/blocking-Session checks -> existing Event-scoped Guest -> its current unique QR. Raw IDs/parents must agree. Ordinary, platform-flagged and workspace-linked administrators satisfy the same legacy predicates; no membership grant or active-only Event policy is invented. A cancelled/unsaved new Guest or refused model save cannot reach PNG/success. Ordinary model hooks and database unique constraints remain authoritative; true save is not an affected-row receipt.

Creation and optional initial QR issuance share one callback. Import uses one callback per actionable row; generation-missing uses one operation per Guest. There is no nested retry helper around irreversible bytes and no all-or-none import/batch file claim. Caller transactions/savepoints remain supported; a local return is not an outer commit. Actual PDO/QueryException keeps framework handling; ordinary non-SQL callback errors are sanitized inside the callback so lock-shaped text does not become a fake nested SQL deadlock.

## Generation and compatible-image access

Explicit generation intentionally rotates to a new opaque 64-character token, reactivates QR and clears revocation, preserving Guest usage/capacity/cancellation and valid manual codes. Missing-only generation rereads current state: an appeared QR returns generated=false/replaced=false without token, activation, timestamp or byte changes. Existing-QR repair preserves exact credentials/activity/revocation and an existing generated_at. Supported raw existing tokens retain the scanner's 40-128 alphanumeric range; repair does not impose exactly 64, normalize, or silently replace an unusable token. Explicit requested rotation may replace one after current guards.

ensureImage first performs a current primary Event/admin/Guest/QR read composition without the offline write veto. It probes only the existing existence/manual-code metadata substring heuristic; this is not decoding/full PNG/token integrity. A compatible image returns without mutation during offline operation. If repair is required, that composition ends and one fresh mutation callback rechecks the full current/offline prefix, discarding old authority/path assumptions. A QR appearing between them is repaired/preserved rather than rotated. Two compositions are not two mutation retries.

[GuestQrImageService](../app/Services/GuestQrImageService.php)::png/manualCodeFor is write-free. Empty manual codes are generated/saved only by the guarded issuance body; valid strings contain exactly four ASCII digits, including 0000/leading zeroes, and remain exact. Invalid nonempty values, including a trailing newline, refuse. Missing-code persistence preserves the current raw pass type, allowance, used entries and status: if ordinary saving hooks normalize any of those fields, the operation refuses and its SQL rolls back before rendering or byte effects. This retains existing admission state rather than silently repairing it. The injected png call remains compatible with existing renderer mocks. PNG dimensions/manual text/metadata and secure-token URL payload are unchanged. Renderer model snapshots keep its argument mutation from retargeting local byte/model targets; arbitrary callbacks/direct database changes remain trusted limits.

ensureImage returns its QR with a guarded, noncircular Guest/Event display snapshot. Download and ZIP filenames use that Guest so a newly provisioned manual code matches the rendered PNG without a new lazy Event read. This display context is not a permission token or certification of later media. Image preview/download and both ZIP repair callers use the service. Later response delivery, nested read projections and copied static/public URLs remain family 3; this read observation is not media isolation. Future public guest/ticket GETs gain no legacy administrator repair authority.

## Frozen paths and irreversible effects

The fixed QR disk (public at P4-045; the private `guest_qr` disk since P4-047 slice 2), current Event path inputs and exact raw current/destination path scalars are captured. Unsupported raw path types refuse. In the mutation callback, every truthy old path and computed destination receives a primary locking ID-only any-other-QR reference veto before that callback resolves its adapter. Null/empty/literal 0 old paths skip absent-value lookups. No Event/Guest/disk/target-set filter hides a reference; no index or provenance ledger is introduced. Creation's guarded INSERT necessarily precedes its new Guest-specific destination check and may roll back on refusal.

A new destination already present refuses even without a database reference. Repair may overwrite its own exact current raw path after the veto; a different computed destination must be absent. These existence/reference observations are not atomic create-if-absent, alias protection or proof of physical ownership. The earlier read composition may have probed an image; mutation vetoes do not certify those read bytes.

Explicit issuance retains QR metadata -> render/strict-true put -> strict-true different-old-path delete. Repair retains put before path metadata update, preserves a nonnull timestamp, and does not delete a different old repair path. Paths stay frozen independently of renderer/model argument changes. False/throw/cancel stops immediately; no repeated put/unlink, automatic orphan cleanup, afterCommit retirement or rollback file restoration is added. Known SQL rollback can restore rows after new/overwritten/removed bytes remain changed. Partial adapters, real SQL deadlocks, caller retry/rollback and unknown commits remain explicit limits.

## Import binding, continuation and private interruption

Preview rows/token bind canonical selected Event and actor. Confirmation checks that context and consumes the ephemeral pending state before dispatch, retaining a local snapshot. Old unbound/mismatched previews require a fresh upload and change no saved Guest. This prevents ordinary sequential reuse when session persistence succeeds; it is not a durable/concurrent exactly-once claim. Workbook/header/2MB/5000-row/phone/pass validation and name/phone duplicate semantics remain. No contact uniqueness rule is added.

Each actionable row, including a skip, rechecks current authority. reject_if_match performs the existing Event-scoped duplicate comparison on primary within its row callback; a newly appeared match becomes conflict. add_anyway creates a separate Guest/manual/QR instead of updating the match. Existing success/invalid/skipped/duplicate/new result categories remain.

Only the exact inner fixed non-SQL failure object may become a continuable failed row, after framework rollback and restoration of the captured connection object, PDO, transaction depth and PDO-open context. Broad outer sanitation cannot manufacture continuation. Actual SQL, replacement rollback exceptions, callback-success/commit errors or changed context interrupt separately. The existing renderer-before-put failure therefore keeps its known rollback/next-row behavior; unknown outcomes do not become false not-imported claims. Fixed exceptions attach no previous raw cause.

Authority/offline failures propagate; uncertain outcomes stop without normal Import completed success or invented final totals. Earlier committed rows may remain under HTTP autocommit, while caller transactions can still roll back SQL. Private partial rows/Guest IDs/manual codes require a fresh current Event/actor access check; lost authority gets generic 403/404 without private flash data. Narrow [SW](../lang/sw/guest_issuance.php)/[EN](../lang/en/guest_issuance.php) failure/interrupted labels use a supported account preference with SW fallback, preserving global locale and ordinary legacy feedback. Refresh guidance acknowledges possible partial effects and does not promise safe automatic retry.

The redirected import-result page honors the interruption flag: localized interrupted/partial-results text replaces the completion heading, aggregate completion totals are hidden, and only nonempty already-observed row sections appear. It does not claim an uncertain row was absent or completed. Ordinary completed imports retain their existing summary and empty sections. The narrow [import view](../resources/views/admin/guests/import.blade.php) correction belongs to this feedback contract and adds no approved-reference screen implementation.
