## IMPLEMENTED — P4-003 source/isolated HTTP checks (2026-10-22)

A distinct customer account can sign in by existing email/phone/password, remember its session, recover through its registered email and reach only its protected read-only workspace home. Raw customer identity IDs must be canonical positive integers within PHP range before Eloquent casting; new customer role never becomes admin/scanner/platform. Primary web account refresh precedes role checks. The independent EN/SW home selects only its own active owner/manager memberships, with fresh account predicates, real workspace parents, fixed 15-row pagination, escaped names and private no-store/no-referrer headers. It neither composes the admin layout nor queries events/guests/files. Legacy staff index and bound read/update/delete now exclude customer/unsupported identities, with fresh primary reads before validation and role predicates repeated on locked write targets. Legacy staff forms cannot create/promote a customer. New customer recovery eligibility is consistent in deferred send and reset; device token eligibility remains active admin/scanner only. Dormant authority/provisioning can accept active customer creators for new workspaces; legacy backfill eligibility is unchanged.

GET /customer is named customer.home and requires a web session plus exact customer role. Unauthenticated visitors go to the shared login; admin/scanner accounts receive403. Customer requests to staff/scanner areas receive403; token login/me/logout deny customers. A workspace membership never changes account mode or assigns a scanner event. Existing identities are not converted automatically and no customer account is created by this task.

New customers use the existing login entry and secure intended-path checks, restricted to /customer. New-identity login clears selected workspace/event/import context. Remember-cookie, current-account/role and password-session checks remain in effect. Recovery keeps generic responses, deferred registered-email delivery, expiry/single use and transactional password/remember/reset/device-token revocation; tests use actual array-mail rendering, never external mail. The device-only predicate keeps active admin/scanner compatibility and prevents new customer web eligibility from broadening bearer access.

The home is an independent Blade document with small local CSS and EN/SW dictionaries selected from the stored language. It shows only own workspace names/roles, own account name, pagination and logout; the empty state is explicit. It reads no event names, guests, QR payloads or files. Submitted account/workspace/event/role/page-size values do not select ownership or expand its fixed 15-row page. Workspace creation/setup links are not exposed yet.

The legacy staff account index contains only admin/scanner rows. Fresh primary role reads deny customer/unsupported bound edits before validation; writers repeat the allowed-role predicate after locking, before password/role/token writes or deletion. Platform flags supply no bypass. This protects customer identity from existing staff CRUD but does not close global event/file administration.
