## CURRENT — facts and independent boundaries

[AuthorityContextResolver](../app/Services/Tenancy/AuthorityContextResolver.php) accepts resolve(Connection, mixed userId, mixed workspaceId=null) and returns [AuthorityContext](../app/Services/Tenancy/AuthorityContext.php). User ID and optional workspace ID must be positive PHP integers; numeric strings, floats, booleans, zero, negatives and out-of-range representations refuse before database/schema reads. No session, auth guard, cached model/relation, event assignment, ledger, workspace name or inferred default supplies authority.

The reader requires only users, workspaces and workspace_users with their required columns and declared single integer id primary keys. It does not depend on event/ledger tables, inserted-ID allocation, FKs, a unique membership constraint or any new migration. Selected account/parent/membership reads are parameter-bound, limited to2 for ambiguity detection and explicitly use the write PDO; schema column/index metadata also uses the primary connection. It performs no unbounded row scan.

| Fact getter | Exact observed condition |
|---|---|
| isAccountEligible() | One matching persisted positive-ID account, canonical active=true and exact current supported admin/scanner role |
| hasPlatformCapability() | Eligible account with explicit canonical is_platform_admin=true; legacy admin alone is insufficient |
| workspaceRole() | Requested persisted workspace plus exactly one matching user/workspace membership, positive canonical identities, canonical active=true and exact owner/manager role; otherwise null |

Canonical true means true,1 or SQL text1 only; other truthy/malformed values confer no capability. Missing/ineligible/ambiguous accounts yield no platform or member facts. Missing/deleted parents, missing/inactive/malformed/duplicate/cross-workspace memberships yield no membership fact while independently observed platform capability remains separate. Scanner-owner is recognized without converting the scanner to a global/platform admin; a flagged platform identity receives no workspace bypass. Omitted workspace never selects a membership or default workspace.

AuthorityContext is final/readonly with private booleans and nullable role, JSON{} and no implicit string conversion. Constructor invariants reject unsupported role values or platform/member facts for an ineligible account. It contains no IDs, PII or permission/allow methods. Public construction is intentional for a value of observed facts; possession or construction is not a capability token.

## CURRENT — freshness, failures and conservation

Every invocation rereads current visible primary rows. No account/flag/membership context cache is used. A caller can still retain an old value, and an existing database transaction has its own visibility; action code must define its locking/revalidation and must not treat this value as a grant. The resolver preserves the caller transaction level and never begins, commits, rolls back or locks rows.

[AuthorityContextException](../app/Services/Tenancy/AuthorityContextException.php) reports only invalid_identifiers, invalid_prerequisites or database_unavailable with the fixed message Authority context could not be resolved. Original exceptions, SQL, bindings and private data are discarded without previous context or logs. Unsupported/unsafe schema does not trigger repair or fallback to the configured default.
