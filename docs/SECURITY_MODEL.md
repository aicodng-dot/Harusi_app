## TARGET — access chain

Authenticate → active account → workspace membership/role → event ownership or scanner assignment → resource ownership → action permission. Platform privileges are separate and support access is auditable. Never authorize from a selected session event, posted workspace ID, hidden field or guessed URL. Use scoped binding/queries and policies with denial tests.

- Passwords use Laravel hashing; web sessions regenerate at login, invalidate at logout; remember tokens supported and hidden. Rate-limit auth/recovery by IP/identifier. Recovery response is generic and only uses registered email, with no OTP cost.
- Android tokens are random, hashed at rest, expiring/revocable and device-labelled; verify account and event permissions each request. Never store plaintext passwords or tokens in URLs/logs. Offline authorization has a bounded validity and explicit revocation limits.
- Admission uses one shared service, authoritative capacity checks, row locks and persisted retry identity. Offline counters require one master authority plus reconciliation for disconnected devices.
- Store invitation/private exports and offline files outside public document root. Validate upload type/content/size, sanitize names, isolate paths, authorize every download and define signed-link expiry. QR tokens/manual codes are admission capabilities even without guest PII.
- Credentials remain in server environment; exclude secrets/data/backup bundles from Git and web roots. Redact log context; minimize guest/contact/admission data and specify retention before automation.
- Verify Meta signatures before processing statuses; replay-safe event handling and tenant-bound message logs. Delivery/media access must not create public indefinite guest-data links.
