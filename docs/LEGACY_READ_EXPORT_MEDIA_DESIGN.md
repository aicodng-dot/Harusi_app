## Frozen context and read composition

Proposed LegacyAdminReadProjection owns typed, materialized read results; proposed LegacyQrMediaDelivery owns buffered administrator media responses. Names describe the intended narrow implementation, not delivered services. Controller validation/pagination/presentation remains separate. Do not add customer permissions or a generic Phase5 service hierarchy.

Capture canonical original/current actor identity, explicit selected Event, any direct Guest PK/Event lineage, normalized filters/sort/page and selected Guest IDs before SQL. Use PositiveIntegerId and existing safe identity rules. Invalid actor refuses 403; invalid selected/direct resource lineage refuses 404. Capture after the existing selection middleware's deliberate absent-selection behavior; add no resolver/default fallback. Never retarget a later query, row, filename or callback from session, mutable request or cached relations. Archived/cancelled selected legacy Events remain eligible; no active-only rule is introduced.

Each read bundle uses one default-connection transaction attempt, with primary locking reads for exact unowned Event then exact current active administrator, followed by scoped root/related rows in stable PK order. The actor predicate stays raw role exactly admin and known true activity, including existing platform/workspace-linked legacy administrators under those same predicates. The stricter scanner/other-creator rules below govern decoration only and cannot silently remove that actor compatibility. It performs no DML, manual-code allocation, render repair or offline write-veto check. Use SQL namespace predicates before private model hydration and raw canonical identity/parent postchecks. Root or operation failure returns no partially prepared private result. Sanitize non-SQL adapter/serializer failures inside the callback; actual PDO/QueryException retains framework handling before fixed outward feedback. Do not retry byte reads or turn concurrency-shaped renderer messages into nested deadlocks.

Primary selection alone does not defeat a caller's repeatable-read snapshot. The proposed implementation therefore uses locking row materialization for data on which current projections depend, rather than claiming ordinary SELECT or an aggregate FOR UPDATE certifies all contributing rows. Compute aggregate arithmetic from the scoped materialized scalar fields. Keep SQL search/date/filter and ordering semantics; do not replace database LIKE/collation with a different PHP matching algorithm. Paginated counts must be derived from the same authorized filtered root identity set, with existing page sizes, without admitting foreign relations through count/search queries.

Caller transactions/savepoints remain supported; there is no new root-only prohibition. A local return is not an outer commit, and locks may remain owned by the caller. Multiple queries are not a universal serializable snapshot against arbitrary writers. Direct current membership probes and any SQL subquery visibility relied on for User classification must be explicitly tested on synthetic MySQL under root and caller RR/RC composition before claiming those semantics. Do not infer them from SQLite builder instrumentation. No new isolation-level change, whole-response retry or transaction held through network transfer is proposed.

Materializing rows may increase memory use and lock breadth, especially for statistics and large exports. Preserve ordinary/empty/large response behavior without silent truncation, hidden row limits or a new asynchronous export feature. Selected engine and load observations must assess the actual chosen queries; source acceptance does not prove hosting throughput or unlimited export capacity.

Other administrator pages using this layout need a bounded standalone layout projection that refreshes the actor and safely projects optional selected context/catalogue. Catalogue/settings pages must not suddenly require a selected Event. An explicitly captured family-3 Event cannot silently switch during layout composition. This shared read dependency does not reopen their completed writer/transaction contracts or offline mutation services. Existing session flash text/form CSRF handling remains presentation state, not permission for resource reads.

Views receive scalar/immutable projections or an adapter with no lazy SQL behavior. Later Blade rendering must issue no private-data SQL, filesystem repair or session-based resource retargeting. ## Export preparation and response boundary

Prepare the complete authorized CSV/XLSX bytes inside the read bundle before returning the response, including serialization success. Keep StreamedResponse shape because existing streamedContent controls depend on it; its callback emits captured bytes only. No database/session/model/repair access occurs in that callback, including before headings. The fixed template remains write-free and contains no private projection.

Keep CSV headings, column order, filenames/MIME and the existing TAB formula protection. Keep XLSX eleven columns, text typing/leading zeroes, numeric allowance/use columns and ordinary/empty/large workbook semantics. Derive download filenames from guarded Event/Guest/manual-code scalars, never lazy-load Event or reread selection. No additional credential/path/URL column appears.

This is authorization at response preparation. A later account revocation, Event transfer, session change or outer caller rollback does not retroactively withdraw already prepared or delivered bytes. Tests must mutate context after preparation and prove frozen output with zero new private queries, not claim a late clean 403. Symfony sends headers before deferred content; a callback abort cannot promise to replace an already-sent status. Do not describe this as continuous transfer authorization or export revocation. Apply private no-store policy to private HTML/export/media responses; it cannot recall old caches or downloads.

## Guarded PNG and complete ZIP delivery

Retain the existing PNG/download/all-ZIP/selected-ZIP routes. No public capability or new endpoint is needed. Image repair stays P4-045: finish its read/mutation composition before beginning delivery. Never hold a delivery transaction around a public mutation method or treat ensureImage's returned model as reusable authority. A needed repair has exactly its existing one mutation attempt and offline veto; healthy reads remain available offline. Repair never becomes implicit QR rotation.

Fresh delivery rechecks captured Event/admin and all current Event-scoped Guest/unique-QR identities on primary. Freeze every exact raw path and filename input from that state. Require safe relative QR keys within the chosen private root: refuse absolute/drive/NUL/traversal/ambiguous separators rather than normalizing to a different target. Before adapter resolution/get, globally veto any other QR reference to each exact path, excluding only its current QR PK. No Event filter may hide a reference. Check the complete selected current set and all path/lineage vetoes before ZIP byte access; do not return a silently reduced selected archive.

The complete-set rule concerns delivery-byte reads: earlier separately guarded compatible-image probes or repairs may already have occurred. Every such probe must satisfy the shared key/root/reference policy below. For all-ZIP, freeze the initially eligible existing-QR Guest ID set before repairs and revalidate that exact set for delivery; concurrent newcomers wait for the next request, and a removed/moved member refuses the whole response. Selected-ZIP freezes its normalized requested set and likewise refuses rather than silently reducing it.

Use one fixed private adapter and buffer all authorized image bytes before constructing success. A delivery get must return a nonempty string; null, non-string, empty or thrown outcomes produce fixed sanitized failure before success. This is byte availability, not PNG/credential integrity verification. All ZIP members and archive serialization must succeed before archive output. Refuse unsupported ZIP32 entry-count, filename-length, size or offset bounds before packing a successful archive; do not truncate members or wrap format fields. Preserve existing entry filenames, manual-code snapshots, allowance suffixes, archive filenames and empty/all/selected behavior. An earlier member's separately authorized repair may remain if a later member/delivery fails; no all-or-none mutation claim follows from withholding the archive. Current revoked/inactive QR downloads remain administrator-compatible.

Use existing MIME types, safe quoted inline disposition for preview and attachment disposition for download/ZIP, Cache-Control private/no-store/max-age=0 and X-Content-Type-Options nosniff. These bounded endpoints ignore Range/If-Range and send the full authorized 200 body; do not advertise ranges or add Content-Range. No ETag/Last-Modified/304 authorization shortcut, X-Sendfile redirect or public URL is introduced. Fixed localized operational feedback includes no raw SQL, adapter path, token or cause logging; authority stays generic 403/404. Later transfer/external replacement/caller limits remain explicit.

## Dedicated storage and the existing writers

Choose one fixed guest_qr local/private disk rooted at storage/app/guest-qr-private outside every web-public root, with throw=true and report=false and no URL, serve/temporary-URL or storage-link facility. Strict exception handling must produce only the fixed outward failure, without raw adapter reporting. Verify configured root/actual parent boundaries before byte access; refuse missing/unsafe configuration or roots under a public root. Trusted directories, aliases and external symlink changes still require actual-host controls. Private visibility by itself is not HTTP isolation.

All four byte readers, issuance compatible-image probe/issue/repair and deletion must resolve that same disk through one narrow shared storage policy. Validate every truthy raw old/new/delivery key before adapter effects, including exists/get compatibility probes, destination checks, puts and deletes. Preserve null/empty/string-0 absence behavior; a truthy unsafe key is a fixed failure, never a missing-image signal that triggers repair. Keys remain exact relative strings: reject absolute/drive/UNC/URL forms, NUL/control bytes, backslashes, colon, empty/dot/dot-dot path segments and local filesystem alias forms such as trailing dot/space or reserved device segments. Permit ordinary historical relative keys outside qr-codes rather than silently imposing a new prefix or renaming them. Trusted-root/alias limits still apply.

Before the compatible-image fast path reads existing bytes, apply the same current global positive-reference veto used by delivery, excluding only its current QR ID. The existing mutation/deletion reference guards remain before their effects. Shared/unsafe/readiness failures must not fall through to repair. Before Storage::disk construction, validate the configured fixed local driver, required flags, nonempty absolute root and existing real root/parent boundaries; refuse missing roots and unsafe parent/symlink/public-root aliases. Then resolve the adapter and verify its actual local root matches the validated configuration before any asset exists/get/put/delete. A cached adapter or arbitrary remote/custom adapter must not bypass the policy. Trusted local wrappers used to observe failures must retain the same validated local root; tests must not replace the policy with an unchecked adapter. Alias/TOCTOU protection against an external privileged writer is an actual-host prerequisite, not a universal source guarantee. Tests can use a real TEMP local fake root through the same production policy, without a testing-only bypass.

Preserve raw qr_image_path relative keys, tokens, manual codes, counters/status/history and current byte/model ordering, shared-reference vetoes, strict outcomes, retry limits and offline behavior. No per-row disk schema, opportunistic public fallback, dual write, request-time migration or migration-driven regeneration is added. Missing private storage is not a reason to look in public storage. Existing ordinary repair behavior is available only after a correctly prepared deployment; it is not evidence that migration succeeded.

This is an explicit storage-location dependency of families 1/2, whose authority contracts remain accepted. Later P4-047 must review their narrow fixed-disk/shared-path/root/probe-veto changes and the corresponding compatibility delta together with family 3. These additions protect the new private-storage composition; they do not reopen unrelated callbacks or write receipts. It may mechanically adapt ordinary-QR test fixture/probe/assertion disk names to guest_qr and explicitly configure/validate their unique TEMP local roots, preserving every prior case identity/count, assertion count and semantic byte check. Shared-probe refusal is a deliberate strengthened boundary; any existing assertion genuinely conflicting with it must be recorded and independently reviewed, never silently weakened to keep a count. No testing-only production branch or renamed public/private alias may hide the change. The nine existing QR-coupled fixture classes are AdminGuestImportTest, AdminGuestManagementTest, AdminQrCodeGenerationTest, AdmissionScannerTest, LegacyGuestDeletionTest, LegacyGuestIssuanceTest, LegacyGuestQrWritesTest, LegacyGuestWritesTest and MultiEventSupportTest. Adapt only ordinary-QR disk operations; retain unrelated public-storage preservation sentinels and offline disk selection. This design task changes none of those 371 tested-source bytes.

The public disk/link may still serve unrelated assets. Do not remove unrelated files or assume actual inventory from source searches. A source denial for the old canonical QR static prefix must precede existing-file bypass where the supplied web-server configuration supports it; equivalent actual-host/alias/CDN denial and retirement is a release gate. PHP/controller authorization cannot deny a copied static file that the host serves directly, and one Apache rule does not certify Nginx, alternate roots or arbitrary old copies.

## Gated cutover, partial outcomes and restoration

1. Before real operations, establish legitimate asset/ownership inventory, DB-plus-file/key backup/restore, intended roots/aliases, maintenance and all-writer fencing. This design authorizes no actual copy/delete, deployment or ownership decision. Private manifests may contain paths/IDs/checksums; ordinary output is aggregate and sanitized.
2. Inventory every persisted QR path association across legacy and owned Events without inferring ownership. Classify unsafe/shared paths, missing bytes and unmodelled copies. Ambiguity blocks automatic retirement. Preserve exact source bytes/checksums and SQL metadata; missing files are reported, never silently rendered as proof of a copy.
3. While fenced, copy approved bytes into an empty protected root using strict success, destination collision refusal and checksum comparison. Keep originals quarantined from HTTP. Do not rotate tokens, alter manual codes, update paths/counters/status or call render repair while copying. Byte equality is not proof of PNG/token integrity or historical provenance.
4. Deploy coherent reader/writer/deleter disk selection and static denial while still fenced. Verify root exclusion, old URL/alias denial for logged-out/foreign callers, no-store authorized responses, exact approved bytes/credentials and relevant cache invalidation before reopening access. Runtime root validation refuses an absent or unsafe private root; complete-copy readiness is a separately evidenced operator gate before reopening writers/access. An existing root does not prove migration completion, and request-time image repair must never be counted as copy verification.
5. Keep rollback copies/manifests protected. Roll back a matching code/storage pair to an authorized protected copy while retaining old-static denial. Never recover by restoring public access. Retirement/deletion of source copies is a separately authorized retention operation; partial copies or deletions stop with evidence and are not undone by SQL rollback.

Existing browser caches, saved images/archives, screenshots, third-party copies and backups cannot be recalled by moving storage or purging one cache. Prior preview max-age=300 matters. Stable QR credentials remain valid by design; incident-driven revocation/rotation requires a separate explicit decision. [Recovery script](../scripts/recover-wedding-data.php) restores SQL metadata from supplied PNG information but does not copy images into a disk; any later authorized restore must stage/verify corresponding protected bytes before reopening access. No perfect erasure or DB-only media restoration is promised.
