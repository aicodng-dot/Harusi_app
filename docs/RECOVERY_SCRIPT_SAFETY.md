# Legacy recovery apply safety

## IMPLEMENTED — P3-019 (2026-10-21)

The existing [recovery script](../scripts/recover-wedding-data.php) now refuses --apply unless the bootstrapped Laravel environment is exactly local or testing. It writes the fixed message "Recovery apply is allowed only in local or testing environments." to stderr and exits 2 before resolving CSV/QR paths or parsing input. Production, staging, unknown, blank, mis-cased and whitespace-suffixed labels are denied. The guard reads the effective Laravel application environment. Executable cases used absent configuration caches; behavior under a cached deployment was not separately exercised.

Without --apply, the existing dry-run validation/output remains available. Exact local/testing with the tested nonexistent base-CSV path continues to reach existing usage exit 1. The original CSV/QR parser and allowed writer body are unchanged; this is not production account setup or a replacement recovery workflow.

## Limits

Executable CLI cases used absent config caches; cached deployment behavior was not separately exercised. The metadata-only test asset does not prove PNG/QR decoding or authenticity.
